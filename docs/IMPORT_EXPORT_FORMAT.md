# 生词本 JSON 导入导出格式规范

本文档定义生词本用于数据迁移和批量操作的 JSON 文件格式。

## 示例

```json
{
  "notebooks": [
    "四级词汇",
    "阅读积累"
  ],
  "words": [
    {
      "word": "abandon",
      "translation": "v. 放弃；抛弃",
      "phonetic": "əˈbændən",
      "note": "注意与 give up 的区别",
      "notebook": "四级词汇",
      "addedAt": "2026-09-01T20:15:30+08:00"
    },
    {
      "word": "serendipity",
      "translation": "n. 意外发现美好事物的运气"
    }
  ]
}
```

## 文件要求

- 文件必须是合法的 JSON，顶层必须是一个对象。
- 文件使用 UTF-8 编码，扩展名为 `.json`。
- 应使用缩进排版，便于阅读和手工修改；建议使用 2 个空格缩进。
- 导出文件建议命名为 `wordbook-export-YYYYMMDD-HHmmss.json`。
- 导出整个生词本，不受当前搜索内容或分册筛选影响。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `notebooks` | 字符串数组 | 否 | 分册名称列表，用于保留没有生词的空分册；省略时视为没有额外分册。 |
| `words` | 对象数组 | 是 | 生词列表，可以是空数组。 |

分册名称去除首尾空白后不能为空，最长 40 个字符。同一文件内的分册名称不允许重复，比较时不区分大小写。

## 生词字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `word` | 字符串 | 是 | 英文单词或短语。去除首尾空白并按应用规则规范化后不能为空。 |
| `translation` | 字符串 | 是 | 释义。去除首尾空白后不能为空，最长 4000 个字符。 |
| `phonetic` | 字符串 | 否 | 音标，最长 100 个字符；省略时为空。首尾的 `/` 会在导入时移除。 |
| `note` | 字符串 | 否 | 个人批注，最长 4000 个字符；省略时为空。 |
| `notebook` | 字符串或 `null` | 否 | 所属分册名称；省略、`null` 或空字符串均表示未分册。 |
| `addedAt` | 字符串 | 否 | 加入时间，采用包含时区的 ISO 8601 格式；省略时使用导入时间。 |

同一文件内不允许出现重复生词，比较时不区分大小写。

## 导入规则

1. 导入前应完整解析并校验文件；任一内容不合法时拒绝整个文件，避免部分导入。
2. 导入采用合并更新方式，不清空现有数据。
3. 文件中的分册不存在时创建；已存在同名分册时直接复用。
4. 生词不存在时新增，并采用文件中的 `addedAt`；缺少该字段时使用导入时间。
5. 生词已存在时更新释义、音标、批注和所属分册，但保留本机原有的加入时间。
6. 生词引用的分册不在 `notebooks` 中时，导入器也会自动创建该分册。
7. 字段类型错误、字段超长、无效时间、重复生词或重复分册均视为格式错误。
8. 错误提示应尽量指出具体位置，例如 `words[3].translation`。

## 导出规则

- 始终输出 `notebooks` 和 `words`。
- 没有音标或批注时可以省略对应字段。
- 没有所属分册时可以省略 `notebook`。
- 导出时应保留生词的 `addedAt`。
- 分册按名称排序，生词按 `word` 排序，使多次导出的结果稳定且便于比较。

## 向下兼容约定

本格式不设置版本字段。后续扩展必须保持对本文格式的兼容：

- 现有字段的名称、类型和含义不得改变。
- 已定义的必填字段不得新增限制。
- 新增内容应使用可选字段，并为字段缺省提供合理行为。
- 导入器必须忽略无法识别的字段，而不能因此拒绝文件。
- 若未来出现无法兼容的需求，应另行定义新的文件格式和扩展名，不改变本格式的解释方式。
